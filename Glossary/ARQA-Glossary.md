# ARQA Glossary

This document provides definitions for key terms and acronyms used across the ARQA platform documentation.

## A

*   **ADR (Architecture Decision Record):** A short text file that captures an important architectural decision made along with its context and consequences.
*   **API (Application Programming Interface):** A set of rules and protocols that allows different software applications to communicate with each other.
*   **ARB (Architecture Review Board):** A governance body responsible for reviewing and approving significant architectural decisions and ensuring alignment with enterprise standards.

## B

*   **BDD (Behavior-Driven Development):** An agile software development process that encourages collaboration among developers, QA, and non-technical or business participants in a software project.

## C

*   **CI/CD (Continuous Integration/Continuous Delivery):** A set of practices that automate the building, testing, and deployment of software, enabling frequent and reliable releases.
*   **Clean Architecture:** A software design philosophy that separates the elements of a design into ring levels, ensuring that the inner rings (business logic) are independent of the outer rings (UI, databases, frameworks).

## D

*   **DDD (Domain-Driven Design):** An approach to software development that centers the development on programming a model that has a deep understanding of the processes and rules of a domain.

## E

*   **EAB (Enterprise Architecture Board):** A high-level governance body responsible for overseeing the overall enterprise architecture strategy and ensuring alignment with business goals.
*   **EDA (Event-Driven Architecture):** A software architecture paradigm promoting the production, detection, consumption of, and reaction to events.

## G

*   **GRB (Governance Review Board):** A body responsible for overseeing policy adherence and resolving governance-related issues across the platform.

## I

*   **IaC (Infrastructure as Code):** The process of managing and provisioning computer data centers through machine-readable definition files, rather than physical hardware configuration or interactive configuration tools.

## M

*   **MDM (Master Data Management):** A comprehensive method of enabling an enterprise to link all of its critical data to one file, called a master file, that provides a common point of reference.
*   **MLOps (Machine Learning Operations):** A set of practices that aims to deploy and maintain machine learning models in production reliably and efficiently.

## N

*   **NEAF (ARQA Enterprise Architecture Framework):** The overarching framework providing a structured approach for designing, implementing, and managing the ARQA platform.

## O

*   **OAS (OpenAPI Specification):** A broadly adopted industry standard for describing modern APIs.

## S

*   **SIEM (Security Information and Event Management):** A software solution that aggregates and analyzes activity from many different resources across your entire IT infrastructure.
*   **SLA (Service Level Agreement):** A commitment between a service provider and a client regarding the level of service expected.
*   **SLI (Service Level Indicator):** A carefully defined quantitative measure of some aspect of the level of service that is provided.
*   **SLO (Service Level Objective):** A target value or range of values for a service level that is measured by an SLI.
*   **SSOT (Single Source of Truth):** The practice of structuring information models and associated data schema such that every data element is mastered (or edited) in only one place.

## T

*   **TDD (Test-Driven Development):** A software development process relying on software requirements being converted to test cases before software is fully developed.

## X

*   **XAI (Explainable AI):** Artificial intelligence systems designed to be transparent and interpretable, allowing humans to understand how decisions are made.
